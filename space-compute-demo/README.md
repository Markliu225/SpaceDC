# Space Compute Demo

**English** · [中文](README.zh-CN.md)

A digital twin of an **orbital compute data center** — an Omniverse-rendered satellite streamed into a React web app and driven by a FastAPI physics engine. You can click any component for live telemetry, reconfigure the deployable solar / radiator geometry from the UI, and watch the real-time power and thermal physics respond.

## Architecture

```
 Browser (React + Zustand)  ──WebRTC──►  Omniverse Kit App (USD viewer)
        │      ▲                                   │
        │      │  state (5 Hz)                     │  reads /state, /satellite_config,
        ▼      │                                   ▼  /twin_geometry; reloads layers
   WebSocket / REST  ◄────────────────────►  Backend (FastAPI)
                                              physics + state engine
```

| Dir | What | Port |
|-----|------|------|
| `web/` | React + TypeScript + Zustand + Three.js shell; WebRTC viewport with a local fallback scene | 5173 (dev) |
| `backend/` | FastAPI state engine (orbit + power + thermal physics) + WebSocket broadcast | 8001 |
| `ov_app/` | Omniverse Kit app + extensions (`space.demo.scene` / `.selection` / …); WebRTC stream | 49100 |
| `usd/` | USD stages — `satellite.usda` (lights + camera) sub-layers `twin_satellite.usda` (the body) | — |
| `tools/` | USD generators + a GL-free preview renderer | — |
| `assets_raw/` | source `.usdz` (backbone / solar / radiator) — large, kept out of git | — |
| `data/`, `docs/` | mock cases, specs | — |

## The satellite model

The body is generated by **`tools/gen_twin_satellite.py`** → `usd/twin_satellite.usda`, built on the `SpaceDcBackbone.usdz` spine:

- **Spine + compute** — a vertical truss with a thruster module at each end, a central tank / reaction-wheel pack, and four quadrant racks (±Y × upper/lower). Each rack holds 3 open shelf-frames → **12 server blades**.
- **Solar wings** — two wings deploy along **±Y** on thin booms off the central brackets; each wing is a number of **2×2 panel clusters** (`solar_panel_3d_model.usdz`, gap-free), cells facing **+X** (the sun). Panels are only ever added along the two sides.
- **Radiators** — two panels deploy along **±Z** on booms off the spine ends, **perpendicular** to the solar wings (faces ±Y). Each is a single **2 : 5** panel meeting the boom on its short edge; size and ratio are adjustable.

Geometry is parameterised at runtime via `usd/twin_params.json` (written by the backend; git-ignored). A GL-free software renderer, **`tools/render_usd.py`**, previews any stage without launching Kit.

## Interactive features

1. **Enlarged viewport** — the Twin page gives the Omniverse window most of the screen; side/bottom panels are compact.
2. **Component-level interaction** — clicking a server, solar wing, radiator, or backbone part opens its info card (matched from the selected prim path).
3. **Deployables editing** — the *Deployables* controls add/remove solar clusters (sides only) and resize / reshape the radiators; each change regenerates the USD model and reloads it in Kit.
4. **Real-time physics** — solar illumination · panel area × efficiency · GPU workload · device power · radiator area × emissivity all feed a live power / thermal balance shown in the status cards and component panels. Editing the geometry changes the numbers immediately.

## Getting started

```bash
# Backend  (Python 3.11, USD/pxr installed in the venv)
cd backend
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app:app --reload --port 8001

# Web
cd web
npm install
npm run dev            # http://localhost:5173

# Omniverse Kit app — see LAUNCH.md
```

**One click:** double-click **`start_all.bat`** to launch the backend, web dev server, and Kit streaming app together (see [LAUNCH.md](LAUNCH.md)). Stop with `stop_all.bat`.

## Tooling

| Script | Purpose |
|--------|---------|
| `tools/gen_twin_satellite.py` | Generate the satellite USD (reads `usd/twin_params.json`) |
| `tools/render_usd.py` | GL-free software renderer — preview any USD/USDZ without Kit |
| `tools/inspect_backbone.py`, `tools/analyze_slots.py` | Geometry / slot surveys for the backbone |

## Notes

- Large `.usdz` assets (backbone, solar, radiator panels — ~75 MB each) are git-ignored; keep them locally under `usd/assets/` and `assets_raw/`.
- The backend regenerates `usd/twin_satellite.usda` on a geometry change and bumps a version; the Kit scene extension reloads that layer live.
