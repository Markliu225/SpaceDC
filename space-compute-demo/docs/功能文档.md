# space-compute-demo 功能文档

> 1MW 级在轨数据中心数字孪生 demo。Web 是主 UI，Omniverse Kit 通过 WebRTC 把三维场景流送进浏览器，FastAPI 后端是业务状态的唯一权威源。

## 1. 项目定位

`space-compute-demo` 是一套 "Web + Omniverse 流式三维 + Python 物理引擎" 的演示性数字孪生：

- 演示一个 1MW 级太空数据中心卫星（DGX 算力载荷 + 太阳能阵 + 散热 + 下行）在轨运行的完整闭环；
- 演示在轨推理 vs 全地面回传两种工作模式的对比；
- 演示一个海事目标识别业务从拍摄 → 推理 → 下传 → 交付的完整任务流；
- 演示一套围绕卫星本体 + 数据中心机舱的三维可视化资产（地球 + 轨道 + 卫星外观 + 内部机舱走廊）。

## 3. 五个 Web 页面 — 功能清单

所有页面共用 [`AppShell`](../web/src/components/AppShell.tsx)：顶部品牌 + 路由导航（Overview / Satellite Twin / Task / Control）、模拟时钟 `T+HHH:MM:SS`、LIVE/OFFLINE 指示灯、Play / Pause / Reset 三按钮；底部挂一个全局唯一的 [`StreamMount`](../web/src/components/StreamMount.tsx)，把 WebRTC `<video>` 用绝对定位铺到每页 `<SceneEmbed>` 上。

### 3.1 OverviewPage — 全局态势 (`/`)

文件：[web/src/pages/OverviewPage.tsx](../web/src/pages/OverviewPage.tsx)

- 进入页面自动 `change_camera({preset:"overview"})`，Kit 切到地球 + 轨道 + 移动卫星图标视角；
- 右侧 `StatusCardGrid` 用 14 张卡片显示卫星 + 地面站实时遥测（轨道类型、经纬度、高度、光照、太阳输入、负载/平台功耗、GPU 型号 / 利用率、温度、电池 SOC、下行带宽、地面站可见性、任务状态），数值越界用 ok / warn / bad 三档着色（如温度 > 75 ℃ 标 bad、SOC < 30% 标 bad）；
- 底部 `EventLog` 显示最近 8 条事件（任务跃迁 / 错误码 / 选择变化）。

### 3.2 SatelliteTwinPage — 卫星孪生体 (`/satellite`)

文件：[web/src/pages/SatelliteTwinPage.tsx](../web/src/pages/SatelliteTwinPage.tsx)

- 进入自动切到 `satellite` 相机预设（Kit 替换为 `satellite.usda` Stage：完整 LUMID 卫星外观 + 内部 DGX 阵列特写）；
- 顶部 4 个视图模式按钮：Structure / Power / Thermal / Compute（Phase 1 占位，按钮 disabled，Phase 2 接通后会发 `set_mode`）；
- 右侧复用 `StatusCardGrid`；
- 计划中的部件状态表 + 功率/温度/电量曲线在 Phase 2 接入（依赖 `selection_changed` + ECharts）。

### 3.3 InteriorPage — 机舱内部 (`/interior`)

文件：[web/src/pages/InteriorPage.tsx](../web/src/pages/InteriorPage.tsx)

- 进入自动切到 `interior` 相机预设，Kit 加载 [usd/interior.usda](../usd/interior.usda)：白色机舱壳 + 两侧各 4 个 42U 机柜（PDU + 3 排 DGX + 服务器 + SN4600 网络交换机）+ 末端 DCP 液冷单元构成"空气墙"；
- 用于演示 1MW 级算力机舱的物理布局；
- 工具栏只标题"INTERIOR"。

### 3.4 TaskExecutionPage — 任务执行 (`/task`)

文件：[web/src/pages/TaskExecutionPage.tsx](../web/src/pages/TaskExecutionPage.tsx)

- `Start Task` 按钮 → `start_task({case_id:"maritime_case_01"})`，后端返回一个 `task_update` 消息，新建 `task-<timestamp>`，类型 `maritime_detection`，输入 5120 MB；
- Mode 切换器：On-Orbit / Ground-Only（→ `set_mode`），用于 Phase 4 的延迟 / 下行量对比；
- 任务卡片实时显示 id / type / state / 输入大小 / 结果大小 / 进度 / 识别目标数 / 告警数；
- 7 阶段相位轨道（idle → created → capturing → inferencing → packaging → downlink → delivered），按当前 `task.state` 高亮 + 已完成阶段加完成态；
- Phase 1 占位；完整状态机 + mock 遥感图 + 检测框 overlay 在 Phase 3 落地（由 [space.demo.task_maritime](../ov_app/exts/space.demo.task_maritime/) 在 Kit 侧叠加海域 AOI + DrawLines 下行链）。

### 3.5 ControlComparePage — 参数对比 (`/control`)

文件：[web/src/pages/ControlComparePage.tsx](../web/src/pages/ControlComparePage.tsx)

- 左侧参数面板：Orbit (LEO/SSO)、GPU (H100/H200/B200/MI300X)、Load (low/medium/high)、Sunlit 复选框；任意值变化即 `set_parameters`；
- 右侧 Outputs 实时卡片：Solar / Payload / Temp / SOC / GPU Util / Downlink（来自 1 Hz `state_update`）；
- Phase 4 接入双对比图（延迟 / 下行总量），目前是占位说明。

## 4. 后端能力（FastAPI）

文件：[backend/app.py](../backend/app.py)、[backend/state_engine.py](../backend/state_engine.py)、[backend/models.py](../backend/models.py)

### 4.1 HTTP

- `GET /health` — 返回 `{ ok, sim_time_s }`；
- `GET /state` — Kit 侧轮询用（Omniverse 自带 stdlib 没有 websockets，所以走 HTTP poll @ 5 Hz）；返回当前 `StatePacket`。

### 4.2 WebSocket `/ws/state`

- 建连即先推一帧 `state_update` 快照；
- 之后按 1 Hz 主动广播 `state_update`；
- 接收的所有命令均走统一 Envelope `{type, ts, payload, request_id}`，返回 `ack`。

接受的命令：`play / pause / reset / set_time / set_parameters / set_mode / start_task / select_object / change_camera`。

### 4.3 StateEngine — Phase 1 占位物理

[backend/state_engine.py](../backend/state_engine.py) 用一个 1 Hz 异步 tick loop 推进：

- 轨道：周期 90 s（演示加速），倾角 60°，圆轨道；输出 lat / lon / sunlit；
- 太阳输入：日照时 4200 W，地影 0；
- GPU 负载：`0.15 + 0.35 * sin(t/20)` ；
- 负载功耗：`400 + 1800 * util` W，平台功耗恒定 600 W；
- 温度：一阶趋近 `30 + 45*util` ℃；
- 电池 SOC：净功率积分；
- 地面可见性：`sin(t/30) > 0.4` 决定，可见时下行 120 Mbps。

> Phase 2 将把现有 Kit 扩展里的 `orbital_mechanics / solar_array_model / thermal_model / battery_model` 真正移植到 `backend/services/`。

### 4.4 案例加载

[backend/case_loader.py](../backend/case_loader.py) 从 `data/cases/<case_id>/case.json` 读 mock case。海事案例目录已建（`data/cases/maritime_case_01/`），具体 JSON 在 Phase 3 写。

## 8. 通讯协议（API 摘要）

完整定义在 [docs/api_spec.md](api_spec.md) 与 [backend/models.py](../backend/models.py)。

统一 Envelope：

```json
{ "type": "<command>", "ts": 1713720000.123, "payload": { ... }, "request_id": "uuid?" }
```

Web → Backend：`play / pause / reset / set_time / set_parameters / set_mode / start_task / select_object / change_camera`。

Backend → Web：
- `state_update` (1 Hz) — 包 `sim_time_s + SatelliteState + GroundStationState + 可选 TaskState + camera_preset + running`；
- `task_update` (事件驱动)；
- `selection_changed` / `camera_changed` (回声)；
- `error` / `ack`。

频率：1 Hz 业务 tick，Web 不做物理推导。Kit 侧用 5 Hz HTTP poll + 单调钟插值，让卫星图标的运动平滑，不被 1 Hz 离散更新拽出"卡顿"。

## 11. 阶段路标

- **Phase 0**（已冻结）— API 与 5 页 UI Spec 定稿。
- **Phase 1**（当前）— 流式骨架贯通：Web 能渲染 + Backend 1 Hz 占位物理 + Kit 切 Stage + WebRTC 嵌入。
- **Phase 2** — 把现有大 Kit 扩展里的真实物理模块（轨道力学 / 太阳能 / 热模型 / 电池）迁到 `backend/services/`；接入 Selection / Timeline / Camera 三个占位扩展。
- **Phase 3** — 海事案例完整 7 阶状态机 + mock 遥感图 + 检测框 + DrawLines 下行链。
- **Phase 4** — 双模式延迟 / 下行量对比图（ECharts）+ CompareMetrics 端到端。

## 12. 已知限制

- WebSocket 单点：所有客户端共享一个 `ConnectionManager`，没有房间 / 鉴权；
- 后端是单进程内存态，无持久化；
- Kit 与 Web 共用一份 `request_id` 但目前 ack 不带任何业务返回；
- `start_task` 只创建一条任务记录，没有阶段推进 — Phase 3 才补；
- `gui_assemble.py` 依赖本地 Tkinter，不在容器环境工作。
