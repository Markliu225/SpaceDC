# SpaceDC Demo 论文写作计划

目标是一篇 ACM MobiCom 风格的 demo 论文，正文两页加一页参考文献，ACM 双栏模板。系统名为 SpaceDC，全文只用这一个系统名，实现层内部名称不出现。文献解析笔记在 related_work 目录，定位论证与审稿意见预案在 POSITIONING.md。

## 一、引言底稿

低轨卫星正从通信节点演进为携带 GPU 的在轨算力平台。Google 论证了单星 28 千瓦的算力卫星，Starcloud 规划吉瓦级在轨集群，而已飞行的算力载荷只有几十瓦，设计与飞行经验相隔三个数量级。

然而这类系统难以研究与评估。在轨数据中心尚不存在，同量级原型的建造与发射成本高昂、周期以年计，设计与研究问题无法在真实系统上得到实验回答。低轨星座研究曾面对同样的处境，社区依靠仿真与实验平台展开工作，Hypatia 与 StarryNet 支撑星座网络研究，Celestial 支撑边缘软件研究，Rhone 支撑卫星计算研究。空间数据中心的研究同样需要自己的实验平台。

这一场景要求平台复现的行为与以往不同。空间数据中心的核心量是计算吞吐，而吞吐由整星物理逐秒决定，卫星每轨进出地影，发电在满功率与零之间切换，数十千瓦的废热经辐射板排出，辐射板同时吸收太阳热流，芯片温度升高即降频。平台若不把供电、散热与计算作为一个耦合系统求解，就无法回答这一场景的基本问题。

现有平台建于各自的研究问题之上，都没有把这一耦合作为求解对象。仿真器 Rhone 的功耗与热模型由一颗已飞的 40 瓦级小卫星约两千个轨道周期的遥测拟合，其论文自述评估新卫星需要那颗卫星的遥测。StarryNet 的能耗取自真实立方星的实测，轨道边缘计算的仿真器不含热模型。在轨数据中心的可行性研究采用稳态估算，Suncatcher 对散热仅有一句说明，Starcloud 以半页平板估算支撑五吉瓦集群，Turyshev 也声明闭式方程不能替代瞬态地影下的热分析。这些模型的能量与热或来自对已建成硬件的实测，或来自稳态假设，没有一个从卫星的设计本身算出，而尚未建造的卫星只有设计可用。

因此，对一颗尚未建造的数十千瓦算力卫星，现有工具无一能回答它在轨每分钟可以提供多少吞吐。

我们提出 SpaceDC，据我们所知是第一个把计算吞吐作为轨道、光照、发电、电池、温度与 GPU 调频逐秒耦合求解输出的数字孪生平台。辐射板面积与涂层、太阳翼、电池化学与容量、GPU 型号与数量、轨道六根数均为机理模型的可改输入，因此平台可以评估尚未建造的设计。轨道、电源与热控对 STK 11.6 逐通道验证的 51 项判据全部通过，24 小时发电量误差不超过 0.4%，地影时刻差不超过 5 秒，温度分段均值差不超过 0.4 K。GPU 推理模型对已发表的 V100 功率封顶实测研究完成校准，通过 52 项检查。

演示中，用户通过四步流程配置卫星，最多四个设计变体与在线仿真同步推进比较，结果以三维渲染呈现。平台在演示场景中给出一个具体结论，石墨涂层辐射板发射率最高，但在光照区自吸收的太阳热超过其散热能力，散热裕量为负，换用光学太阳反射镜涂层后转正。

## 二、摘要

八到十句，与引言同一主线压缩。趋势与量级差一句，GPU 吞吐在轨道上由整星供电散热决定一句，现有工具的物理来自实测或稳态假设一句，无一能算尚未建造卫星的吞吐一句，SpaceDC 定位一句，可改设计输入一句，STK 验证数字一句，GPU 模型校准一句，演示能力一句。

## 三、系统概述章节

配架构图 Fig. 1，分四段。

第一段，物理引擎。引擎以固定步长推进，每步依次求解轨道位置、光照与地影、发电功率、电池电量、载荷功耗与温度。轨道采用 SGP4 传播，太阳位置采用解析模型，地影采用圆锥本影与半影模型，星下点与地面站几何基于 WGS-84 椭球。热模型包含设备耗散、太阳吸收、地球反照与地球红外四项热流。

第二段，计算性能模型。GPU 推理吞吐由解析模型给出，输入为功率预算、模型规模、批量与上下文长度，输出为频率、吞吐与芯片温度。功率预算取供电能力与温度限制中的较小者，温度限制项把结构温度与吞吐耦合起来。模型对公开的 V100 功率封顶测量研究完成校准。

第三段，交互层。配置流程按平台、结构、载荷、任务四步组装卫星，每次修改后在独立引擎实例上试算并返回供电与散热裕量。方案比较功能使二至四个设计变体与在线仿真同步推进，差异实时显示在遥测曲线上。三维场景由 Omniverse 渲染并推流到浏览器。

第四段，验证方法。以 STK 11.6 为参照，在相同轨道根数与时间轴上导出双方的星历、光照区间、地面站可见窗口与温度序列并逐项比较。热模块与 STK 空间环境模型在相同的吸收率、发射率、面积与耗散参数下比较。

## 四、演示与评估章节

先给出精度表 Table I，再给出两个演示场景。

Table I 各行：轨道位置差在数值精度量级，星下点经纬度差不超过十的负七次方度，地影事件时刻差不超过 4.8 秒，地面站接入窗口起止差不超过 1.0 秒且无漏报误报，24 小时发电量差不超过 0.4%，光照段与地影段温度均值差分别为 0.34 K 与 0.31 K。

场景一，卫星设计。用户从配置流程选择平台，逐槽位配置 GPU，调整辐射板与太阳翼，供电与散热裕量实时更新，运行后进入在轨仿真。此场景给出引言结尾的具体结论及其数字，石墨涂层辐射板在光照区自吸收 21.5 千瓦太阳热，超过其散热能力，换用光学太阳反射镜涂层后裕量由负转正。配界面截图。

场景二，运行期比较。多种辐射板材料的设计变体与在线卫星同步推进，温度曲线随蚀周期分离，温度较高的变体触发 GPU 降频，推理吞吐随之下降，散热设计的代价以每秒 token 数呈现。配遥测曲线截图。

## 八、写作规范

1. 每句话承载一个事实或一个论断，论断有数字或引用支撑。
2. 术语用领域标准说法，系统内部名称不出现。
3. 不用括号与破折号，补充说明写成独立句子。
4. 不用反问、倒装、排比与隐喻，首创声明前加据我们所知。
5. 句子以顺承与因果衔接，单句不超过三行。
6. 同一数字全文只用一种写法。
7. 缩写首次出现给全称，全文缩写不超过八个。
8. 对现有工作只陈述其方法边界，不评判动机，批评性事实优先引用对方论文的自述。
